Philosophy

No magic buttons

Kraftverk is a performance engineering instrument — not a PC cleaner, not a placebo FPS booster, not a cloud service. Every kept change is measured, validated, explainable, and restorable.

If a setting cannot improve measured performance, efficiency, stability, latency, thermal behavior, or the instrumentation used to decide, it does not belong in the product. No fabricated telemetry. No silent irreversible tweaks.

Comparison

Instrument vs placebo “optimizer”

Most consumer “PC optimizers” sell certainty without evidence. Kraftverk is built the other way around.

Dimension Kraftverk Typical placebo optimizer
Evidence Real workloads (KraftBench) + statistical compare Marketing scores, timers, or vague “boost”
Changes Allow-listed, reversible, journaled Registry sweeps, cleaners, one-way tweaks
Honesty Unsupported sensors marked unsupported Invented temps, FPS, or health meters
Hardware Hard AMD-only gate (amd-only-v1) Anything that installs
Outcome Keep or revert with explainable receipts Permanent “optimization” with no rollback story

Evidence loop

Measure → Experiment → Validate → Improve

Product framing is a closed loop. Search always rolls back during exploration; only validated accepts remain applied.

  • 01 Measure KraftBench runs real deterministic work with checksums where practical.
  • 02 Experiment Propose reversible parameter diffs under safe-mode allow-lists.
  • 03 Validate Stability gates and comparison classes vs baseline samples.
  • 04 Improve Commit what helps; restore what does not. Learn and repeat.

Kraft Index

A composite you can explain

The Kraft Index is a weighted blend of category scores from KraftBench. A baseline run’s mean raw composite maps to 10,000; later runs are ratios against that baseline.

Illustrative cascade below — weights are the documented M1 defaults. GPU weight is zero until a real backend exists (no placeholder dilution).

CPU
0.40
Memory
0.20
Storage
0.15
Realtime
0.15
System
0.10
GPU
0.00
Baseline → 10,000

Later: index = (raw / baseline_raw) × 10000. Missing categories renormalize over present weights.

Hardware

AMD systems only

Policy amd-only-v1 is a hard execution gate across CLI, desktop, SDK, agent, and optimizer — not a cosmetic preference. Official binaries target x86_64 Windows and x86_64 Linux.

Supported

  • Architecture: x86 / x86_64
  • CPU: AMD (AuthenticAMD)
  • GPU: none, or AMD only (PCI 0x1002)

Blocked

  • Intel CPU · unknown CPU vendor
  • NVIDIA / Intel GPU when present
  • Mixed AMD+NVIDIA · non-x86 builds
  • Exit codes 20–25 · no production --force
